백엔드 통합 검증 결과 (2026-10-02)

1. 병합 범위
원본 OCR 프로젝트 대비 main Java 코드 변경은 아래 5개 파일입니다.
- controller/NotificationController.java
- service/GateLogService.java
- service/NotificationService.java
- service/OverloadService.java
- service/WeighbridgeService.java
추가 테스트: src/test/java/com/scargo/service/BackendMergeTests.java

2. Java 소스 컴파일
JDK 17.0.12, 프로젝트 Gradle 설정에서 오프라인으로 해석한 실제 의존성과
Lombok/QueryDSL annotation processor를 사용하여 javac로 클래스 생성.
컴파일 명령 종료 코드 0, 소스 컴파일 오류 없음.
단, 컴파일러가 종료 시 JAR 파일을 닫는 과정에서 Windows 접근 오류를 출력했습니다.
따라서 Gradle test/bootJar 전체 빌드가 성공했다고 보장하지 않습니다.
Gradle 9.7.1 compileJava도 같은 JAR 종료 접근 오류로 실패했습니다.

3. 병합 회귀 테스트
JUnit Platform 1.10.2 / JUnit Jupiter 5.10.2 사용.
의존성 및 컴파일된 클래스를 JAR classpath로 직접 실행했습니다.
실행 환경의 Java agent 연결을 피하기 위해 검증 실행에만 Mockito subclass mock maker를 사용했습니다.
프로젝트 제품 코드 및 Gradle 설정은 변경하지 않았습니다.

결과: 7개 실행, 7개 성공, 0개 실패, 0개 건너뜀.
- ENTRY OCR가 최신 PENDING 상하차 작업을 시작하는지
- EXIT OCR가 최종 출차 처리를 호출하는지
- OCR 인식 실패 시 워크플로우를 시작하지 않는지
- 미등록 차량 알림 발송 실패가 게이트 기록 반환과 다른 수신자를 막지 않는지
- 과적 알림 일부 실패 후에도 다른 관리자에게 발송하는지
- 소속 기업 회원 전원 및 관리자에게 개별 과적 알림을 발송하는지
- 재계량 과적일 때만 알림을 보내고 통과 시 추가 알림을 보내지 않는지

4. 검증하지 않은 범위
- 실제 PostgreSQL 연결 및 트랜잭션 롤백/커밋 동작
- 기존 SpringBootTest 애플리케이션 시작 테스트
- 실제 OCR 장비 및 프론트엔드와의 연동
- 실행용 bootJar 생성 및 서버 기동

이 검증은 병합된 서비스 동작을 확인하는 단위 테스트이며,
실제 DB 및 장비 환경에서의 통합 테스트를 대신하지 않습니다.
