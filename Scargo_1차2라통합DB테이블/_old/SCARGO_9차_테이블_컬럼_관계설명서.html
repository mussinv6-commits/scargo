SCARGO DATABASE · 2026.10.16 · 9차 차량 참조 삭제 제한

테이블·컬럼·관계 설명서

최종 적용 DB의 실제 스키마와 검증 결과를 정리했습니다. 8차에서 배차 이후 필수값을 DB CHECK로 보장합니다. 민간계량소는 제거하고 B경로 과적검문소는 유지합니다. 검색·외래키 바로가기·인쇄를 지원합니다.

업무 흐름과 데이터 역할

① 항만컨테이너·물품·차량
운송 건·앱 오더
② 항만→허브원본 shipment_id 필수
컨테이너 차량 구간
③ 허브입고 → OCR → 분류
AMR 이동 → 다중 박스 랙
④ 허브→센터일반 택배차 운행 1회
여러 원본 운송 건 합배송

서울·인천·경기 권역별 센터 1개, 곤지암 허브 1개입니다. 출고 구간의 shipment_id는 NULL이고, 물품은 원래 shipment_id를 유지합니다. item_vehicle_assignments로 여러 원본 운송 건의 물품을 출고 구간 하나에 배정합니다.

대상관리 기준
거점·허브logistics_centers가 주소·좌표를 관리하고 hubs.center_id로 허브 운영 정보를 연결합니다. 앱 조회도 거점 정보를 JOIN합니다.
물품·박스items는 운송장·바코드·중량·원본 운송 건·목적지, parcels는 허브 내 위치·입출고·작업 상태입니다. items 1개에 parcels 최대 1개가 연결됩니다.
랙같은 slot_id에 여러 박스를 보관할 수 있습니다. 칸별 잔여 수량·중량·부피와 EMPTY/OCCUPIED 상태 판단은 백엔드에서 처리합니다.
과적검문소weigh_stations만 사용합니다. B경로 순서: CHECKPOINT-38 → 18 → 36 → 10 → 34. 민간계량소 기능과 테이블은 제거했습니다.
결제·통과결제와 연결된 진입/진출 통과 기록은 수정·삭제할 수 없습니다. 결제 링크 변경·이력 삭제도 차단합니다. 취소·환불은 결제 상태로 남깁니다.

PK=기본키, FK=외래키. FK는 일반적으로 부모 1개에 자식 여러 개를 허용합니다. UNIQUE가 함께 있으면 중복 연결이 제한됩니다. SQL에 적힌 최초 정의가 아니라 PostgreSQL에 전체 적용 후 남은 실제 카탈로그를 문서화했습니다.

핵심 관계 읽기

관계방향·개수와 의미
logistics_centers → hubs거점 1개에 허브 정보 최대 1개. 각 허브는 center_id가 필수입니다. 모든 거점이 허브인 것은 아닙니다.
shipments → items원본 운송 건 1개에 물품 여러 개. items는 원본 shipment_id를 계속 유지합니다.
items → parcels물품 1개에 허브 박스 정보 최대 1개. parcels.item_id는 필수·UNIQUE입니다.
items ↔ shipment_legsitem_vehicle_assignments가 연결합니다. 물품은 여러 구간을 이동할 수 있고 구간 하나에 여러 물품이 실릴 수 있습니다. 항만 구간은 원본 운송 건 일치를 검사합니다.
hubs → zones → slots → parcels허브에 여러 구역, 구역에 여러 랙 칸, 칸에 여러 박스. 박스와 랙의 hub_id가 같아야 합니다.
shipment_legs → 입출고해당 항만 구간에 입고 접수 최대 1건, 해당 출고 구간에 출고 기록 최대 1건. 입출고 차량·허브·구간 방향을 검사합니다.
amr_robots → telemetry/tasks/predictions/maintenance로봇별로 여러 센서·작업·예측·정비 기록이 생깁니다. 예측을 정비 근거로 연결할 때 대상 로봇이 같아야 합니다.
transport_orders → trip_locations/trip_events/handovers오더별 GPS·이벤트는 여러 건, 인계는 최대 1건. 앱 오더는 항만 구간을 연결하며 허브 출고와 역할이 다릅니다.
toll_passages → toll_payments결제 대상 진출/개방식 통과 passage_id는 UNIQUE입니다. 폐쇄식에는 entry_passage_id도 연결합니다. 결제 연결 후 두 통과 기록을 잠급니다.

상태·중량·식별자의 구분

items.status는 전체 배송 상태, parcels.status는 허브 내부 상태, amr_tasks.status는 작업 상태입니다. tracking_no는 운송장, barcode는 물품 스캔 코드, parcel_no는 허브 내부 박스 ID입니다. containers.max_payload_kg는 허용 화물 중량이며 실제 물품 중량은 items.weight_kg, 신고 컨테이너 총중량은 vgm_kg로 구분합니다. 차량의 max_load_ton과 kg 컬럼을 사용할 때 단위를 맞춰야 합니다.

관계 목록은 실제 FK 기준입니다. 업무 순서를 설명하는 화살표는 직접 FK와 다를 수 있습니다. FK가 없는 다형 참조와 업무 상태 전환·과적·동시 작업 제어는 백엔드 구현 영역입니다.

9차 변경 · 차량 삭제 정책

오더·입고·출고가 참조하는 차량은 ON DELETE RESTRICT로 삭제를 차단합니다. fk_order_truck, fk_receipts_truck, fk_dispatches_vehicle 세 외래키에 적용됩니다. 차량 번호를 NULL로 바꾸다가 배차 CHECK나 구간 검증에 실패하는 이전 동작을, 명시적인 FK 삭제 제한으로 바꿨습니다.

활성 오더뿐 아니라 완료·취소 오더 및 입출고 이력도 참조가 남아 있으면 삭제를 제한합니다. 참조가 전혀 없는 차량은 삭제할 수 있습니다. 운영 중지 정책은 별도로 정해야 하며 현재 trucks.status에 없는 INACTIVE 값을 임의로 넣으면 안 됩니다.

테이블·컬럼 개수와 관계 방향은 8차와 같고, 위 세 FK의 삭제 정책이 변경되었습니다. 나머지 업무 흐름 설명은 유지됩니다.

CREATE OR REPLACE FUNCTION public.scargo_validate_order_leg()
 RETURNS trigger
 LANGUAGE plpgsql
AS $function$ DECLARE x RECORD; BEGIN  IF NEW.assignment_id IS NULL THEN    IF NEW.status NOT IN ('CREATED','CANCELED') AND NEW.shipment_id IS NOT NULL THEN      RAISE EXCEPTION '배차 이후 앱 오더는 운송 구간이 필요합니다: %', NEW.order_no;    END IF;    RETURN NEW;  END IF;  IF NEW.shipment_id IS NULL THEN RAISE EXCEPTION 'assignment_id 사용 시 shipment_id 필수'; END IF;  SELECT l.vehicle_no, l.from_center_id, l.to_center_id, l.leg_type,         s.container_no, t.center_id AS terminal_center_id, h.center_id AS hub_center_id  INTO x FROM shipment_legs l JOIN shipments s ON s.shipment_id=l.shipment_id  JOIN terminals t ON t.terminal_id=NEW.origin_terminal_id  JOIN hubs h ON h.hub_id=NEW.dest_hub_id WHERE l.assignment_id=NEW.assignment_id;  IF NOT FOUND OR x.leg_type <> 'PORT_TO_HUB' OR NEW.vehicle_no IS DISTINCT FROM x.vehicle_no     OR NEW.container_no IS DISTINCT FROM x.container_no     OR x.from_center_id IS DISTINCT FROM x.terminal_center_id     OR x.to_center_id IS DISTINCT FROM x.hub_center_id THEN    RAISE EXCEPTION '앱 오더와 운송 구간/차량/컨테이너/거점 불일치: %', NEW.order_no;  END IF;  RETURN NEW; END $function$

 RETURNS trigger
 LANGUAGE plpgsql
AS $function$ DECLARE p RECORD; e RECORD; BEGIN  IF NEW.passage_id IS NULL THEN RAISE EXCEPTION '결제에는 통과 이벤트 passage_id가 필요'; END IF;  SELECT * INTO p FROM toll_passages WHERE passage_id=NEW.passage_id;  IF NOT FOUND OR p.vehicle_no IS DISTINCT FROM NEW.vehicle_no OR     p.tollgate_id IS DISTINCT FROM NEW.tollgate_id OR p.passage_status <> 'PASSED' THEN    RAISE EXCEPTION '결제와 진출/개방식 통과 이벤트 불일치'; END IF;  IF NEW.assignment_id IS DISTINCT FROM p.assignment_id THEN    RAISE EXCEPTION '결제와 통과 이벤트의 운송 구간 불일치'; END IF;  IF NEW.toll_system='CLOSED' THEN    SELECT * INTO e FROM toll_passages WHERE passage_id=NEW.entry_passage_id;    IF NOT FOUND OR e.vehicle_no IS DISTINCT FROM NEW.vehicle_no       OR e.passage_status <> 'PASSED' OR e.detected_at > p.detected_at THEN      RAISE EXCEPTION '폐쇄식 진입 이벤트와 진출 이벤트 불일치'; END IF;  END IF;  RETURN NEW; END $function$
