# 백엔드 최종 병합 안내 (26.10.01)

`scargo_1001.zip`(26.09.30 병합본)을 기준으로, `backend_태수님.zip`과 `backend_길웅님.zip`에서
**병합본 이후에 새로 바뀐 부분만** 골라서 합쳤습니다.
인증 방식·권한 표기(`hasRole`, `ROLE_*`, `principal.id`)는 기존 병합본(A 방식) 그대로 유지했습니다.

## 1. 태수님 쪽에서 가져온 것
- **회원정보 수정 API** `PUT /api/accounts/{id}` + `AccountUpdateRequest` (비밀번호/이름/휴대폰 중 입력한 값만 변경)
  - 원본에는 권한 체크가 없어서 남의 계정도 수정 가능했음 → `hasRole('ADMIN') or #id == principal.id` 추가
  - 원본의 로그인 방식 변경(SecurityContext 직접 저장)은 A 방식과 충돌해서 가져오지 않음
- **야드 / 적재위치 상태 자동 동기화**: `status` 가 `AVAILABLE` 이면 `isAvailable=true`, 그 외는 `false` 로 자동 세팅
  (`Yard`, `LoadingLocation`, `YardService`, `LoadingLocationService`)
  - `PATCH /api/loading-locations/{id}/status` 는 이제 `status` 파라미터만 받음 (`isAvailable` 파라미터 제거)
  - 요청 DTO의 `isAvailable` 필드는 남아 있지만 무시됨
- **게이트 이력 이미지 업로드**: `POST /api/v1/gate-logs`
  - `Content-Type: application/json` → 기존처럼 JSON만
  - `Content-Type: multipart/form-data` → `data`(JSON) + `frontImage` / `rearImage`(파일, 선택)
  - 저장 경로: `/data/scargo/images/gate/` (윈도우면 `C:\data\scargo\images\gate\`)
- `ContainerCreateRequest.reservedCargoInfo` 빈 문자열 → null 변환
- `OverloadController` 기간 조회 `@RequestParam("start")`, `@RequestParam("end")` 이름 명시

## 2. 길웅님 쪽에서 가져온 것
- **게이트 코드(gateCode)로 게이트 지정** (OCR/파이썬 장비 연동용)
  - 등록/수정 요청에 `gateId` 또는 `gateCode` 중 하나만 보내면 됨 (둘 다 오면 `gateId` 우선)
  - 응답(`GateLogResponse`)에 `gateId`, `gateCode` 추가 (`gateName`, `gateType` 는 그대로 → 프론트 수정 불필요)
- `SecurityConfig`: 게이트 이력 조회(`GET /api/v1/gate-logs/**`) 비회원 허용
- 길웅님 버전의 `Gate` 엔티티(Integer ID, update/delete 메서드 없음)는 `GateService` 와 맞지 않아 컴파일이
  안 되는 상태라, 엔티티 구조는 기존(Long ID) 유지하고 **gateCode 기능만** 옮겼습니다.

## 3. 병합 중 고친 것
- `PostController` 글 작성/수정/삭제의 `hasAuthority('ADMIN')` → `hasRole('ADMIN')`
  (세션 필터가 `ROLE_ADMIN` 으로 권한을 주기 때문에 기존 표기로는 관리자도 403이 났음)
- 압축 해제 시 깨지던 한글 파일명 복구

## 4. 참고 / 확인 필요
- DB 변경 없음. (단, 9/30 병합 때의 `manual_merge_260930.sql` 을 아직 안 돌렸다면 먼저 실행)

  SecurityConfig 허용 설정이 추가로 필요합니다. 현재는 파일 저장 + DB에 경로 기록까지만 됩니다.
