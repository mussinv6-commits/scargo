# 백엔드 병합 안내 (26.09.30)

`scargo_260928.zip`(이하 A) 을 기준으로 `백엔드.zip`(이하 B) 의 신규 기능을 합쳤습니다.
Firebase(FCM) 관련 코드는 모두 빼서 별도 zip(`firebase_separated`)으로 분리했습니다.

## 1. 기준을 A 로 잡은 이유
두 프로젝트의 **인증 방식이 서로 달라서** 한쪽으로 통일해야 했습니다.

| | A (채택) | B |
|---|---|---|
| 인증 | `SessionAuthenticationFilter` 가 매 요청마다 세션의 accountId 로 계정 조회 | 로그인할 때 한 번 SecurityContext 를 세션에 저장 |
| 권한 문자열 | `ROLE_ADMIN` → `hasRole('ADMIN')` | `ADMIN` → `hasAuthority('ADMIN')` |
| principal | `AuthenticatedAccountPrincipal`(id, companyId 포함) | userId 문자열 |

A 쪽의 기사 배정, 진입 허가, 업체 기사 목록, 알림 본인확인(`principal.id`) 기능이 모두
A 방식에 의존하고, 프론트(scargo_vue 병합본)도 이 API 들을 사용하므로 A 를 기준으로 했습니다.
**B 에서 가져온 코드의 `hasAuthority/hasAnyAuthority` 는 전부 `hasRole/hasAnyRole` 로 바꿨습니다.**

## 2. B 에서 가져온 것
- 신규: 게이트 마스터(`Gate*`, `/api/gates`), 일상점검표(`VehicleChecklist*`, `/api/checklists`),
  운행일지(`VehicleDailyLog*`, `/api/vehicle-logs`), 타이어 관리(`TireManagement*`), `FileDownloadResponse`
- GateLog: `gate_name/gate_type` 문자열 → `Gate` 외래키 구조로 변경 (Entity/DTO/Repository/Service)
- 게시판: `/bbs`, `/bbs/bbslist` 경로 추가, 첨부파일 다운로드 API (`GET /api/v1/posts/{postId}/attachments/{fileId}`),
  글/댓글 작성·수정·삭제에 로그인 권한 체크
- 알림: 타이어 10만 km 도달 알림 메서드, `NotificationType.TIRE_ALERT`
- 권한 완화(B 정책 반영):
  - 사업자(CORPORATE_APPROVED) 허용: 차량 전체/단건 조회·수정, 게이트 이력 등록·수정, 적재위치 등록·수정·상태변경, 과적 목록/위반/불합격 조회
  - 로그인 회원 전체 허용: 야드 목록/단건/타입별/가용여부별 조회
- SecurityConfig: `/bbs/bbslist`, `/api/posts`, `/api/notices` GET 비회원 허용 추가

## 3. A 쪽을 유지한 것 (B 가 더 오래된 버전)
- `@PathVariable("이름")` 명시 (B 는 이름을 빼서 `-parameters` 옵션 없는 환경에서 400 발생 가능) → B 신규 GateController 에도 이름 추가
- `NotificationType` 은 DB 제약조건에 맞춘 A 값(SYSTEM, NOTICE...) 유지 + TIRE_ALERT 추가
- `OverloadService` 축중 데이터 저장(B 는 `...생략...` 플레이스홀더로 저장 안 되던 버전)
- AdminInitializer 더미 사업자 계정(biz1), 기업 거절 API, 기사 배정/진입허가, CompanyResponse.companyId
- `application.yml` DB 이름은 A 의 `cargo` 유지 (B 는 `scargo`) → 필요하면 바꾸세요
