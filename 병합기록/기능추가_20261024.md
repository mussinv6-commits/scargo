## 적용
1. DB: `DB\추가_20261024_기능4종.sql` 실행 (설치 SQL 이미 넣은 DB 용, 다시 실행해도 안전). 새 DB 에 설치 SQL 부터 넣는 경우에도 이어서 실행
2. 백엔드 재시작 (사진은 실행 폴더의 `uploads\inspections\` 에 저장, `SCARGO_UPLOAD_DIR` 로 변경 가능)
3. 새 의존성 없음 (xlsx 는 `util/SimpleXlsx.java` 로 직접 생성)

## 확인한 것 / 못 한 것
- 확인: xlsx 파일 생성(Python openpyxl 로 열림), 보고서·하역·사진 SQL (PostgreSQL 16 에서 설치 SQL 위에 실행), JS 문법
- 못 함: Java 컴파일, 화면 빌드·실행 (이 환경에서 라이브러리를 받을 수 없음) → 처음 실행 때 STS/`npm run dev` 에서 오류가 나면 알려 주세요

# 추가 2종: 운영 현황판 · 예외/사고 접수 (2026-10-24)

| 기능 | 위치 | 비고 |
|---|---|---|
| 운영 현황판 | 관리자 `운영 현황판`, 허브 화면 `현황판` 탭 · `GET /api/ops/overview` | 하역 대기(대기 시간) · 지연 오더(ETA 초과) · 점검 불합격(7일) · 도크 점유 · 미처리 예외. 30초 자동 새로고침, [하역 완료] 바로 처리 |
| 예외·사고 접수 | 관리자 `예외·사고 접수`, 허브 화면 `예외·사고` 탭 · `/api/incidents` | 파손/씰/지연/차량/안전/기타, 중요도, 처리 상태(접수→처리 중→해결), 담당자, 조치 내용(해결 시 필수), Excel 내보내기 |

- 권한: 현황판 = 관리자·관제(전체)·허브 담당자(소속 허브). 접수 = 관리자·관제·허브·업체·기사, 처리 = 관리자·관제·허브(소속). 해결된 건 재오픈은 관리자만
- DB: `DB\추가_20261024_운영현황.sql` 1회 실행 (표 ops_incidents, 다시 실행해도 안전)
- 확인: SQL(PostgreSQL 16)·JS 문법. 못 함: Java 컴파일, 화면 실행
